# LUBRICA 1.0.33.45 — Recovery Storage Quota Fix

## Исправлено

Ошибка `QuotaExceededError` возникала потому, что полная рабочая база каждые 30 секунд синхронно сериализовалась в `localStorage` под ключом `lubrica-recovery-v2`. Для производственной базы объём JSON превысил квоту браузера, после чего диагностика получала одинаковую ошибку каждые 30 секунд.

### Новая схема recovery

- `IndexedDB` является основным хранилищем полноразмерных recovery-снимков.
- `localStorage` используется только как небольшой аварийный fallback (до 750000 символов).
- 30-секундный recovery-таймер переведён с `saveRecoverySync()` на асинхронный `saveRecovery()`, то есть больше не пытается записать большую базу в `localStorage`.
- При успешной записи в IndexedDB старые большие ключи `lubrica-recovery-v2` и `lubrica-recovery-prev-v2` удаляются, освобождая квоту браузера.
- `pagehide`/закрытие страницы остаётся защищённым: обновляется метаинформация и запускается дополнительная IndexedDB-запись без большой синхронной записи в localStorage.
- Архив предыдущей сессии также хранится в IndexedDB; в localStorage попадает только небольшой архив, если он помещается.
- Ошибка quota больше не создаёт запись в журнале каждые 30 секунд. При полном отказе recovery-хранилищ предупреждение ограничено одним сообщением за сессию.

## Совместимость

- Загрузка recovery сначала идёт из IndexedDB, затем из старых localStorage-ключей для обратной совместимости.
- Существующие данные базы и схема `2.0` не менялись.
- Файл рабочей базы и обычное автосохранение в выбранный пользователем файл не затронуты.
