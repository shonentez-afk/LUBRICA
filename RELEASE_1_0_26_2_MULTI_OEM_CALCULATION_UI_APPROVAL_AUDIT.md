# LUBRICA 1.0.26.2 — Multi-OEM Calculation UI & Approval Audit

Дата: 2026-09-08

## Цель
Проверить экран подшипникового расчёта как пользователь для SKF / NSK / FAG-Schaeffler / NTN-SNR / Timken и убрать неоднозначности между расчётным значением, OEM-источником и инженерным утверждением.

## Исправления интерфейса
- Верхний статус переименован в «Сводная достоверность» и объясняет шкалу A/B/C/D/X.
- Достоверность и источник теперь показаны отдельно в блоках: досмазывание, первичное заполнение, периодичность.
- Убрана формулировка, будто базовый интервал всегда «SKF/OEM»; источник базы теперь явно отделён от выбранного производителя.
- Каталожная масса показывает производителя исходной записи. При выборе другого OEM экран прямо сообщает о межбрендовой справочной массе и снижении достоверности.
- Полная замена оставлена отдельным подтверждаемым значением и не копируется из первичного заполнения.
- Поля «Утверждённое...» отделены от расчётных результатов.

## Правила утверждения
Любое заполненное утверждённое значение теперь требует собственного источника:
- доза досмазывания;
- первичное заполнение;
- полная замена;
- периодичность.

Значение должно быть больше нуля. Уровень X запрещает автоматическое принятие результата, но не блокирует сохранение вручную подтверждённого значения при наличии источника.

## Матрица пользовательской проверки Auto OEM на 6212
- SKF: доза B (OEM method); периодичность X без базового интервала.
- NSK: доза A (OEM exact); периодичность A при 1800 rpm из локальной NSK OEM-таблицы.
- FAG/Schaeffler: Auto даёт X и требует явного выбора weekly/monthly/yearly/multiyear; явный monthly даёт B.
- NTN-SNR: доза B; периодичность X без базового интервала.
- Timken: Auto даёт X; требуется результат/входы OEM tool либо вручную подтверждённое значение.
- Применение метода SKF при выбранном NSK допускается только как явно межбрендовая инженерная оценка D с предупреждением.

## Дополнительный найденный и исправленный дефект
После перехода с 1.0.26.1 на 1.0.26.2 обнаружен version-gate в синхронизации полной замены: проверка была жёстко привязана к `multi-oem-1.0.26.1`. Без исправления 1.0.26.2 мог бы снова использовать старое поведение и переносить первичное заполнение в полную замену. Проверка заменена на совместимость со всей веткой `multi-oem-1.0.26.x`.
