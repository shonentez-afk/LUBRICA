# LUBRICA 1.0.33.48 — Oscillating / Linkage Arrangement Constructor

## Что добавлено

- Добавлен универсальный конструктор **«Система качания / рычажный механизм»** (`oscillating_linkage`).
- Конструктор не привязан к конкретной производственной линии и собирает механизм из ролей: КШМ, шатун, тяга, ось вращения, компенсатор, кронштейн, рычаг, коромысло, эксцентрик и палец.
- Существующие типы `connecting_rod`, `axis` и `crank` сохранены; новый engine использует их как элементы общей схемы, а не заменяет прежнюю классификацию.
- Добавлено распознавание левой/правой стороны, номера линии, иерархии, `componentId`/`equipmentId` и фактических ТМЦ.

## Главное правило точек

- Название элемента механизма **не является основанием** для создания точки смазки.
- Точки создаются только для подтверждённых физических мест обслуживания: подшипник, UC/UK, SKF SNL + внутренний подшипник, подшипник скольжения, втулка, смазываемый палец, шарнир, сферический шарнирный подшипник, шарнирная головка, направляющая или другая подтверждённая пара.
- `Требует уточнения`, `Необслуживаемый / нет соединения` не создают виртуальных точек.
- Для подшипниковых вариантов требуется фактический ТМЦ или введённое инженером обозначение.
- Имена точек формируются по физическому месту, например `Шатун левый · верхний шарнир`, а не просто `Подшипник`.

## Интеграция

- Используется существующий `LubricaCandidateFinalizer` и существующая модель Structure → Node → Lubrication Point → Task.
- Для подшипников сохраняется существующий путь Bearing Calculator; UC/UK и SNL остаются в действующих housed/SNL calculation contexts. Новых параллельных формул не добавлено.
- Ручное создание оборудования получило тип `Система качания / рычажный механизм`; после сохранения открывается тот же engine, что используется для импортированных данных.
- В Structure добавлена карточка конструктора в стиле существующих Unified Equipment Constructor Cards.
- Простой режим показывает человеческую модель и подтверждение; Экспертный — IDs, raw designation и связь с ТМЦ. «Обоснование» использует существующее централизованное окно источников.

## Transactional lifecycle

- До нажатия `Создать точки` новые точки и мероприятия не записываются.
- `Отмена` не выполняет сохранение.
- Повторное подтверждение использует стабильный `candidateOriginKey` и не создаёт дублей.
- После удаления созданной точки повторное подтверждение создаёт одну новую точку и одно соответствующее мероприятие без накопления дублей.

## UI / UX

- Добавлены адаптивные сетки конструктора для широких и узких окон.
- Длинные названия элементов и ТМЦ допускают перенос без наложения на соседние поля.
- При ширине до 980 px поля переходят в 2 колонки, до 640 px — в 1 колонку.
- КШМ не получает жёстко заданное число соединений: пользователь добавляет только фактически существующие места.

## Известные ограничения

- Если фактическая конструкция соединения неизвестна, LUBRICA намеренно не создаёт точку и оставляет `Требует уточнения`.
- Для КШМ число соединений не угадывается автоматически.
- При ручном SNL/UC-UK подтверждении инженер должен выбрать фактический ТМЦ/обозначение; housing/bearing details не выдумываются.
- Pixel-level headless Chromium screenshot-аудит не выполнен из-за ограничений Chromium/DBus в тестовом контейнере; responsive-разметка проверена статическими UI-contract тестами.
