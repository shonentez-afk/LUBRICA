# LUBRICA 1.0.13 — Calculation to task & schedule units hotfix

## Исправлено

### 1. Расчёт теперь связан с мероприятием

После сохранения подшипникового расчёта результат сразу записывается в текущее мероприятие:

- для `Досмазывание` — расчётная доза `calculatedDoseG`;
- для `Полная замена смазки` — расчётное полное количество `calculatedFullFillG`;
- если инженер заполнил поле `Утверждено`, утверждённое значение сразу переносится в `task.quantity.approved`;
- расчётный интервал и утверждённый интервал сохраняются в `task.schedule`.

Если утверждённое количество ещё не задано, Карта смазки показывает рассчитанное количество с пометкой **«расч.»**, но не считает его утверждённым. Это сохраняет инженерный принцип: расчётное и утверждённое значения — разные сущности.

### 2. Календарная периодичность получила явные единицы

В карточке мероприятия теперь периодичность задаётся двумя полями:

- значение;
- единица.

Для стратегии `По календарю` доступны:

- дни;
- недели;
- месяцы;
- годы.

Для стратегии `По наработке` единица автоматически становится `часы работы`.

Для стратегии `По состоянию` интервал отключается как неприменимый.

В БД дополнительно сохраняются структурированные поля `calendarValue`, `calendarUnit` и `runtimeHours`, при этом `legacyText` остаётся совместимым с существующим планированием маршрутов (`4 нед.`, `3 мес.`, `500 ч`).

### 3. Создание мероприятия из Структуры

В диалоге мероприятия также добавлена отдельная единица периодичности. Базовая периодичность в мастере создания точки теперь также вводится как значение + единица.
