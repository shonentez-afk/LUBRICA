# LUBRICA 1.0.30.8 — Renewal Approval & Fallback UX Fix

## Исправлено

- Блок «Инженерный fallback и ручное переопределение периода» больше не раскрывается как полноценный параллельный калькулятор в штатном REITZ-сценарии. После включения технических параметров он остаётся отдельным закрытым `details` и явно сообщает, участвует ли инженерный контур в текущем расчёте.
- Поля P/C, предельные обороты, вращение наружного кольца, ручная база, коэффициент условий и speed diagnostics не выглядят входами REITZ KXE без явного выбора соответствующей методики/fallback.
- Ручные поля «Утверждённое количество / интервал» для полного обновления перенесены в отдельный закрытый блок «Ручное утверждение / отклонение от расчёта».
- Если сохранённое утверждение отличается от текущего расчёта, интерфейс явно показывает несоответствие. Старое значение не выдаётся за текущий расчёт.
- При переключении периода полного обновления на SKF SNL fallback старое утверждённое значение периода и его источник сбрасываются, чтобы историческое число (например 1265 ч) не оставалось рядом с новым расчётным значением (например 2300 ч).
- При возврате полной замены в состояние «оставить на уточнение» старое утверждение периода также сбрасывается.

## Не менялось

- Математика REITZ KXE, SKF SNL, ZLG, NSK и Universal не изменялась.
- Calculation version contract не повышался: UI-hotfix не делает ранее утверждённые расчёты устаревшими сам по себе.
