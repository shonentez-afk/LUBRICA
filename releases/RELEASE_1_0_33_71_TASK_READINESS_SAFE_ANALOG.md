# LUBRICA 1.0.33.71 RC — готовность мероприятий и безопасные аналоги

**Статус:** Stage 3, functional release candidate, автоматическая приёмка по GitHub CI. Пользовательское руководство и скриншоты не меняются. Предыдущая версия исходников: 1.0.33.70 RC; опубликованная контрольная ZIP-сборка: 1.0.33.70 RC1.

## Суть

- Read-only движок `qa/task-readiness.js`: семь шагов для *каждого мероприятия* (физическая точка, операция, материал, норма, периодичность, источники, утверждение). Несколько мероприятий одной точки имеют отдельные статусы.
- В существующем «Контроле» — компактные карточки готовности, фильтры линии/состояния/текста, постраничный список, действие «Открыть» и раскрываемая инженерная причина без полного редизайна.
- Исправлено опасное поведение `Заполнить по аналогу`: совпадающая маркировка подшипника сама по себе не считается подтверждённой конструкцией. В интерфейсе инженер подтверждает физическое соответствие, причину и источник.
- Система запрещает перенос между разными моделями/размерами/непривязанными узлами; запрещает изменять точку с утверждёнными/отключёнными мероприятиями или участием в маршруте/факте; не переносит физические ID, геометрию, смазку, фактически установленную в корпусе, и подтверждённые OEM-расчёты.
- Доза/интервал из аналога сохраняются только как `quantity.analogSuggested` / `schedule.analogSuggested`, а не как `approved`/готовый `legacyText`. Новые мероприятия остаются `review`; автоматического утверждения нет.
- Массовое безусловное копирование по одноимённому подшипнику на другие линии отключено. Будущий перенос полной схемы на другой агрегат потребует сопоставления физической конфигурации, source provenance и отдельной приёмки.
- Сохраняется фактически подтверждённый статус *физической* точки; перенос влияет только на предлагаемые параметры мероприятия.
- Тест `test/test_release_1_0_33_71_task_readiness_safe_analog.js` проверяет правила, конфликтные ветки и read-only прогон принятой производственной базы PP-53736.
