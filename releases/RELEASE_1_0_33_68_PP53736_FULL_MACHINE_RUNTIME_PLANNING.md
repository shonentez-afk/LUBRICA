## Назначение

Версия 1.0.33.68 завершает программную сквозную приёмку machine profile Izoteh PP-53736 после 1.0.33.67 и закрывает обнаруженный в ходе этой приёмки пробел календарного планирования мероприятий с периодичностью в моточасах.

`Филиал_завода__Техно__г._Юрга(20260923-051134).json`.

## Runtime-hour planning

До этой версии `routes/route-planning.js` работал с календарными периодами, но не имел доказательной модели преобразования 200/800/5000 ч в даты.

1.0.33.68 добавляет безопасную модель:

- `planningAnchorDate` — явная первая дата, задаваемая пользователем;
- `runtimePlanningHoursPerDay` — опциональная плановая наработка оборудования, ч/сутки;
- без ч/сутки создаётся только явно заданная первая дата и предупреждение о том, что повторения не прогнозируются;
- при заданной плановой наработке повторные даты рассчитываются из исходного интервала в моточасах;
- после завершённого маршрута последняя фактическая дата становится новым anchor прогноза;
- plan item хранит provenance: `planningBasis`, `runtimeIntervalHours`, `runtimePlanningHoursPerDay`, `runtimeForecast`;
- скрытого универсального коэффициента «моточасы → календарные дни» нет.

## Конфигурационный workflow SEW

После уточнения пользовательского workflow отдельные field blockers для PP-53736 отсутствуют.

- `5000/500 h` = 5000 ч рабочий цикл + 500 ч first service.
- Для K37/KF37R17/R77/S37 M1–M6 выбирается пользователем при создании/настройке карты.
- После выбора LUBRICA автоматически выдаёт OEM-объём масла.
- Для R77 №5–№8 Line 1 чертёжный M3 остаётся hint/предупреждением; он не перезаписывает user-confirmed положение.
- Незавершённый или конфликтующий выбор остаётся `review` до настройки карты, что является штатным lifecycle, а не дефектом релиза.
