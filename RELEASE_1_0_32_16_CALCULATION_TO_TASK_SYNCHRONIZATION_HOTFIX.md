# LUBRICA 1.0.32.16 — Calculation To Task Synchronization Hotfix

## Исправленный дефект
В экспертном режиме после изменения условий эксплуатации текущий расчёт мог измениться (например, UCP 212: 2250 ч → 563 ч), но при нажатии «Применить расчёт» в мероприятии сохранялось старое утверждённое значение 2250 ч.

Причина: старое `approvedRelubeIntervalHours` продолжало иметь приоритет при `syncBearingCalculationToTask()`. В простом режиме текущий результат переутверждался автоматически, а в экспертном режиме старое approval сохранялось даже если пользователь не вводил его вручную в текущей сессии.

## Новая логика
- Если рассчитанное значение изменилось, а поля ручного утверждения в экспертном режиме пользователь не редактировал, «Применить расчёт» автоматически заменяет устаревшее approval текущим результатом.
- Если пользователь действительно изменил поля ручного утверждения/источника в текущей сессии, его экспертное отклонение сохраняется.
- После записи CalculationPackage активное мероприятие дополнительно синхронизируется через `syncBearingCalculationToTask()`.
- Обновляются `quantity`, `schedule.approvedHours`, `schedule.runtimeHours`, `schedule.legacyText`, источник и выбранное мероприятие.
- Для утверждённого мероприятия статус `approved` не сбрасывается автоматически: меняется его рабочий цикл, а не workflow-статус.

## Проверяемый сценарий
UCP 212 / LUBRICA Universal 3.2 / 300 об/мин:
1. Было утверждено 8.5 г / 2250 ч.
2. Изменены условия эксплуатации, текущий расчёт = 8.5 г / 563 ч.
3. Нажать «Применить расчёт».
4. В карточке мероприятия должно сразу отображаться 563 часов работы.

Расчётные формулы и OEM MethodResolver не менялись.
