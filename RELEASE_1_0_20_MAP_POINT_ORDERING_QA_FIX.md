# LUBRICA 1.0.20 — Map point ordering & QA non-destructive audit

## Исправлено

В Карте смазки мероприятия отображались в порядке их создания (`tasks[]`). Если мероприятие добавлялось позднее к старой физической точке, например LP-000017, оно попадало в конец таблицы и визуально казалось отсутствующим рядом с LP-000016/LP-000018.

Теперь Карта сортирует отображение прежде всего по физической точке (`lubricationPointId`) и только затем по мероприятию. Поэтому новые мероприятия старой точки сразу отображаются внутри правильного блока точки.

Пример: TASK-000085/TASK-000086, добавленные к LP-000017 значительно позже остальных задач, теперь показываются между LP-000016 и LP-000018.

## Контроль

Удалена автоматическая очистка пустых candidate-точек из QA-аудита. Контроль теперь только диагностирует `POINT_WITHOUT_TASKS` и никогда сам не удаляет физические точки. Изменение данных выполняется только явным действием пользователя через Структуру/Карту.

## Инварианты

- одна физическая точка = один визуальный блок;
- одно мероприятие = отдельная строка данных;
- порядок создания мероприятия не влияет на место точки в Карте;
- QA является недеструктивным аудитом.
