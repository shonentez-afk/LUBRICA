# LUBRICA 1.0.33.10 — Partial Area4 Update Import

## Что исправлено

Исправлен повторный импорт корректирующих Excel-файлов, содержащих только листы `Позиции` и/или `ТМЦ` без листов связей `Структура позиций` и `Структура ТМЦ`.

Ранее такой файл определялся как `unknown` и полностью пропускался. Теперь он распознаётся как `area4_update` и используется как безопасное обновление уже существующей структуры по внешним кодам.

## Правила обновления

- существующая позиция ищется по `Position` → `equipment.externalCode`;
- существующий ТМЦ ищется по `Asset` → `components.externalCode`;
- `Description` обновляет отображаемое наименование в точности из корректирующего файла;
- обновляются только поля, реально присутствующие и заполненные в корректирующем файле;
- существующие `lineId`, `areaId`, `parentEquipmentId`, `equipmentId` и иерархия не перестраиваются;
- неизвестные коды не создаются без листов связей, а попадают в предупреждения;
- повторный импорт не создаёт дубликаты;
- неуспешный/пустой корректирующий импорт больше не перезаписывает `meta.lastImportBatchId`.

## Проверка на фактических файлах

Проверено последовательное применение:

1. `Участок камеры волокноосаждения(1).xlsx` — полный `area4`;
2. `Участок камеры волокноосаждения исправление №1.xlsx` — `area4_update`.

Результат: обновлено 107 позиций и 588 ТМЦ, количество объектов не изменилось, родительские связи и привязки ТМЦ сохранены, исправленные наименования с `Линия №1 / Линия №2` применены.

Добавлен регрессионный тест `test_release_1_0_33_10_partial_area4_update.js`.
