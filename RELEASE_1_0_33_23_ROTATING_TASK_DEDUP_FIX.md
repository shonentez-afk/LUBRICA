# LUBRICA 1.0.33.23 — Rotating Task Dedup Fix

Исправлена регрессия 1.0.33.22 в Universal Rotating Assembly Constructor.

## Причина
Конструктор создавал мероприятие «Досмазывание» с временным activityType `relubrication`, тогда как канонический Bearing workflow и LUBRICA Universal используют `regrease`. После применения расчёта Bearing Engine не находил существующее мероприятие и создавал второе.

## Исправления
- Universal Rotating Assembly Constructor теперь создаёт только `regrease`.
- Candidate Finalizer нормализует старый alias `relubrication` в `regrease`.
- Database Normalizer автоматически ремонтирует базы 1.0.33.22:
  - одиночный `relubrication` переводится в `regrease`;
  - известная пара `relubrication + regrease` на одной точке объединяется в одно мероприятие;
  - при объединении приоритет отдаётся мероприятию с расчётными/утверждёнными данными;
  - материал и инструмент из кандидатного мероприятия сохраняются, если отсутствуют у расчётного;
  - ссылки маршрутов на удаляемый дубль переводятся на сохранённое мероприятие;
  - обычные несколько `regrease` мероприятий на одной точке НЕ объединяются, поскольку несколько событий на точку являются допустимой моделью LUBRICA.
- Task Editor понимает старый alias как `regrease` и не создаёт новый дубль при повторном применении расчёта.

## Ожидаемый результат
Для каждой опоры вращающегося узла после расчёта остаётся одно мероприятие:
`Досмазывание → рассчитанная доза / рассчитанный период`.

Пример: `15 г / 2250 ч` вместо двух строк «Досмазывание».
