# LUBRICA 1.0.33.43 — Conveyor SNL Housing Context Fix

Исправлена потеря контекста корпуса SKF SNL для подшипниковых точек ленточных конвейеров.

## Причина
Подшипниковый калькулятор определял SNL в основном из `fanLubrication` или названия самой точки. У точек конвейера физическое место называется «Приводной вал · левая опора», а корпус `SNL 530`/`SNL 520-617` хранится в исходном компоненте структуры (`componentBinding.structuralText` / `sourceComponentId`). Поэтому обычный Universal Bearing Calculator видел только `23230` или `23220` и не включал SKF SNL service policy.

## Исправление
- Контекст корпуса теперь разрешается из исходного элемента структуры, component binding и имени точки.
- Поддерживаются `SNL 530`, а также составные обозначения вроде `SNL 520-617`.
- Для конвейерных точек SNL открывается тот же специализированный SKF SNL расчёт, что и для других физических SNL-опор.
- В расчёт передаются `housingFamily=SNL` и точная маркировка корпуса.
- Корпус и внутренний подшипник остаются разными сущностями: например `SNL 530 + 23230`.
- Никакой fan-specific OEM не назначается конвейеру автоматически.

## Контрольный пример
`SNL 530 + 23230`, подача сбоку: рабочая доза по SKF `0.005 × D × B = 129.6 г`; полный рабочий запас корпуса по локальной OEM-таблице — `1700 г`. Интервал обычного досмазывания остаётся инженерным, если application-specific OEM машины не задан.
