# LUBRICA 1.0.7 — исправление инженерного подтверждения кандидатов

Исправлен логический дефект после «Подтвердить и создать».

## Было

Для одного импортированного компонента с двумя физическими точками система создавала два одинаковых узла структуры. Пользовательские названия точек («Подшипниковая опора левая/правая») сохранялись в базе, но в дереве скрывались за названием категории «Подшипник качения». В Карте смазки под Point ID имя физической точки также не отображалось.

## Стало

Для component-кандидата создаётся один узел исходного компонента и несколько физических точек внутри него.

Пример:

Конвейер отсева каменного материала
→ Барабан приводной
  → Подшипниковая опора левая
    → Досмазывание
    → Полная замена смазки
  → Подшипниковая опора правая
    → Досмазывание
    → Полная замена смазки

В дереве отображается реальное имя физической точки, а категория и Point ID остаются вторичной информацией. В Карте смазки под LP-... отображается имя точки.

## Repair существующих данных

Normalizer автоматически объединяет только строго распознаваемые дубли узлов, созданные старым candidate-механизмом для одного component-кандидата. Точки переназначаются на общий узел. Обычные ручные узлы не затрагиваются.
