## 3. Реализация Saw / Cut / Traverse

- `machines/saw-cut-arrangement.js` — один семейный конструктор, без второго расчётного движка: определяет пилы, режущие устройства, каретки, колёса пил и группы; проходит по реальному дереву дочернего оборудования и конкретным импортированным `sourceComponentId`.
- Вызов из привычной правой карточки «Структура» — `Открыть конструктор`. Родительская группа позволяет открыть дочернюю пилу, но **не создаёт в группе смазочные точки**. Дочернее колесо сохраняет принадлежность точек именно своему `equipmentId`.
- Перечень ТМЦ показывает код источника, вид механизма, кандидаты, имеющиеся pointId. Подшипник, мотор, направляющая, цепь, вал и режущее полотно не считаются одним и тем же видом действия. Из списка конструктивных валов можно перейти прямо в существующий `Rotating Arrangement`.
- Инженер добавляет конкретные физические позиции в реестр `equipment.sawCutSurvey`: исходный подшипниковый ТМЦ, расположение, подтверждённый доступ/маслёнка, ссылка на осмотр/OEM. Одной модели ТМЦ разрешено соответствовать **нескольким, но отдельно доказанным** местам. Без явного `serviceable` создаётся **ноль** точек.
- Герметичные `2RS/2CS`, полимерные `IGUS/drylin/OILAMID`, отсутствующий или исключённый ТМЦ **не превращаются в рутинную досмазку**. Для линейного подшипника нужна явная OEM-проверка. Существующие парки OEM-калькуляторов остаются штатными; норма, материал и период не проставляются автоматически.
- Новые физические точки и `review`-мероприятия создаются **только через `LubricaCandidateFinalizer.applyConfirmedSpecs`**, с ключом `component:<sourceId>:saw_position_<positionId>`. Инженерный preview и повторное применение не дублируют точки. Существующие подтверждённые физические места не удаляются/не переназначаются без отдельной инженерной миграции.
- Изменения применяются на клоне базы только после успешного preview. `approved`-мероприятия, маршруты, планы и история не перезаписываются.

## 4. Завершение Rotating Arrangement

- `rotating/rotating-arrangement.js` — новый конструктор на фактических местах для валов, барабанов, роликов, осей. Исходное количество **0/неизвестно**, без автоподстановки двух опор из названия вала или одной модели подшипника.
- Проверяется число **0–6** опор, каждое расположение, исходный bearing ТМЦ, тип обслуживания, подтверждённый доступ к маслёнке/каналу, фото/паспорт/акт. `review` и `not_serviceable` не создают новых точек. Для подтверждения `not_serviceable` также нужен источник.
- Если известна только модель подшипника, без физического места, результат — инженерный черновик `rotatingArrangementSurvey`, **0 точек**. Один source может соответствовать разным проверенным опорам. Герметичные исполнения не получают обычную досмазку автоматически.
- Для ручного оборудования в `structure/entity-dialogs.js` доступно 0–6 опор; поля 5 и 6 добавлены, пустые поля и значение «Неизвестно» не создают ТМЦ. Ручной ввод обозначения сохраняется **на проверке**, но не делает опору подтверждённой.
- Старые существующие точки/статусы не перезаписываются; попытка поменять уже подтверждённый `positionId` требует отдельного согласованного переноса. Центрифуги/охлаждение остаются вне объёма. Именование точек основано на фактическом месте, не на марке ТМЦ.
