# LUBRICA — постоянные инженерные правила предприятия

Этот файл собирает факты и ограничения, которые относятся к фактически установленному оборудованию предприятия. Они не являются универсальными правилами для всех OEM.

## 1. Общий принцип

Фактическая конструкция установленной машины имеет приоритет над типовым шаблоном.

Нельзя:
- создавать виртуальные опоры;
- додумывать внутренние подшипники;
- переносить конструкцию одного производителя на другого;
- считать название/маркировку достаточным доказательством физической схемы.

## 2. Вентиляторы и подшипниковые узлы

### Fan / motor separation
Вентилятор и электродвигатель являются отдельными объектами, если фактическая конструкция действительно содержит оба объекта.

Не создавать отдельный вентиляторный вал/опоры для прямого привода, если рабочее колесо установлено непосредственно на вал двигателя.

### Fan №31 — direct drive
Для вентилятора №31 подтверждён прямой привод: рабочее колесо находится на валу двигателя.

Старый отдельный fan-object:
`E 355/71-40.407 (COMP-0000435)`

не должен восстанавливаться как самостоятельный обслуживаемый вентиляторный узел, если фактическая схема остаётся direct drive.

### SNR ZLG
Для применяемых на предприятии SNR ZLG:
- фактическая конфигурация обслуживания — **2 пресс-маслёнки**;
- не использовать DLG как замену ZLG;
- не считать автоматически «одна маслёнка = один внутренний подшипник».

### SNR DLG
Семейство SNR DLG не используется в текущей fan-bearing логике предприятия.

Не добавлять его в fan-engine без отдельного подтверждённого нового кейса.

### Tröster
Подшипниковые блоки Tröster на предприятии подтверждены только на вентиляторах Ventapp.

Для применяемых Tröster 31–33 T L:
- 2 пресс-маслёнки;
- производитель блока — Tröster, а не производитель вентилятора;
- методика не переносится автоматически на Ferrari или другие вентиляторы;
- формула дозы `Gperiod = 0.005 × D × B` применяется только при подтверждённых D и B фактического внутреннего подшипника.

### Ferrari
На вентиляторах Ferrari встречаются:
- собственные совмещённые подшипниковые узлы Ferrari;
- корпуса/узлы типа SKF SNL.

Нельзя считать любой Ferrari-узел SNL без фактического подтверждения.

## 3. OEM priority

Для REITZ application-specific методики имеют приоритет над общим fallback, когда применимость подтверждена конкретным вентилятором/узлом.

SKF SNL, NTN-SNR ZLG, Tröster, Ferrari и другие семейства должны оставаться отдельными контекстами, без смешивания UI и расчётных правил.

## 4. Материалы и плотность

Расчётный framework понимает плотность как в г/см³, так и в кг/м³ и нормализует единицы.

Для конкретного материала всегда использовать значение из подтверждённой карточки/TDS, а не фиксировать одну плотность как универсальную для всех смазок.

## 5. Расширение

Эти правила описывают текущий парк предприятия, но не закрывают архитектуру.

Если появляется новый вентилятор, новый OEM или новая конструкция:
1. подтвердить физическую схему;
2. найти OEM-источник;
3. добавить модульное правило;
4. добавить targeted test;
5. обновить этот файл только если правило действительно является постоянным для предприятия.
