# R6 — заключительный интеграционный аудит маршрутов LUBRICA

25.11.2026, поверх R5, Draft PR #23. Не менять main или заводскую базу.

## Найдено и исправлено
1. Нормализатор создавал копию, но повторно брал исходные массивы; исправлено. Старое объединение alias relubrication/regrease могло удалить идентификатор, принадлежащий снимку, заданию, ревизии, настроенному сроку или архиву. При наличии защищённой идентичности обе записи сохраняются, отмечаются routeIdentityConflict и исключаются из автоматического включения до инженерной сверки. Исторические документы не переписываются. Неподходящий массив/повтор ID истории отклоняется на входе. Явный disabled имеет приоритет над verified.
2. План items/summary/export теперь read-only; чтение больше не меняет updatedAt. Предпросмотр плана проверяет токен состояния базы и локальной даты; R5 тоже защищён при смене дня.
3. Выбранное незапущенное задание одного маршрута не подменяется другим активным: показывается точный состав только для просмотра с переходом к текущему выполнению. Изменение метаданных запущенного typed задания ограничено допустимыми полями; идентификаторы, дата, снимок, статус и привязка к плану не изменяются произвольным patch.
4. Сохранение поискового запроса при обновлении раздела. Печать из компактного режима и native beforeprint/afterprint с переходом к подробной таблице и восстановлением режима, без второго набора редактируемых полей.
5. CSV зафиксированных заданий: отдельные строки по taskId, исходная/рабочая дата, индивидуальный срок, смена, статус, ревизия, замороженная норма, фактические результаты. Формулоподобный текст экранируется; экспорт постоянных маршрутов сохраняется. Для старого задания без замороженного снимка поля нормы/операции не реконструируются догадкой.
6. Вместимость нескольких заданий одного маршрута: пока одновременно может идти только один его чек-лист, задания в одной смене объединяются для проверки укладки в ресурс одного человека; не раздавать фиктивно параллельно.
7. Повторное использование карты физических точек, инженерной готовности и контекстов для массовой сверки, планирования, подготовки и прогноза. Без отмены проверок QA.
8. Новые тесты: real modules + 48 синтетических физических точек разных категорий, QA без заглушек, восстановление и сохранность ID/сроков/ревизий, точный состав и факт, stale preview, CSV, ресурс. Массовый тест 1200 задач: ожидается 1197 допущенных, 48 групп, 52 недели, повтор без изменений. Предварительный JS-прогон подтверждает эти числа. Полный реальный index.html через Chromium file://, без заглушек State и QA, мастер, выбор второго задания, print lifecycle, CSV download, browser recovery/reload. Старые тесты R1–R5 и конструкторов остаются в полном regression. 

## Приёмка заводской базы
Исходный файл от 05.11.2026 найден в Library только по метаданным; raw materialization недоступна. Никакие заводские данные не выгружать в репозиторий. Не считать синтетические проверки заводской приёмкой.
В ZIP есть `tools/route-r6-audit.js`. При наличии Node.js локально: из каталога сборки `node tools/route-r6-audit.js "D:\\Backup\\factory-copy.json"`. Скрипт только читает JSON и вычисляет агрегаты QA/состава/предложения без применения, без записи/сети. Не печатает идентификаторы точек. Не является ручной приёмкой Edge и не создаёт маршруты на диске. 
Ручная последовательность на отдельной копии: открыть ZIP index.html в Edge, загрузить копию JSON, сверить исключения/маршруты, указать реальные основания сроков, ППР и рабочие минуты, проверить предварительный просмотр и повтор, сохранить отдельный JSON, открыть повторно, проверить план, печать, CSV и recovery. Не создавать рабочие маршруты до завершения K3/M1. 
Ограничения R5 (эвристический прогноз, 1–3 смены и одно выполнение маршрута, отсутствие интеграции АСУ ТП) сохраняются. Автоматическая проверка Chromium не подменяет Windows/Edge и реальный принтер. 

## R6.1 — упрощение мастера (25.11.2026)
Пользователь показал блокирующее сообщение досрочного окна. Основной мастер теперь открывается в обычном режиме: линия/участок, проверка состава, сохранение. Используется тот же R5/R6 транзакционный reconcile; готовые маршруты активируются только при действительном сроке, прочие остаются черновиками. Подтверждённая история может восстановить отсутствующее основание, но новые даты не придумываются. График, ППР, окно, нормы, прогноз и план не применяются скрыто; прогноз не строится в обычном режиме. Дополнительные настройки доступны одним переключателем. Ошибки не показывают пустые KPI; по положительному досрочному допуску кнопка «Выбрать подходящие» выбирает только допустимые календарные мероприятия, моточасы не округляются. 0 отменяет допуск. Сохраняются все проверки, защита истории и ручных/открытых заданий. При отсутствии изменений сохранение неактивно. Тесты R5/R6 дополнены проверками обычного режима, невидимых полей, ошибок допуска и повторного сохранения. Draft PR #23, main/заводская база не изменены; ручная приёмка на копии JSON остаётся.

## R6.2 — участки и ручное сохранение JSON (25.11.2026)
Скриншот пользователя совпал с демобазой (`silos/cupola/forming`), не с заводской структурой. Мастер показывает название открытой базы и явное предупреждение в деморежиме; одинаковые названия участков в режиме всех линий различаются префиксом линии, выбор использует реальные areaId. Старый fromLegacy больше не объединяет участки по одному scope и создаёт разные ID для разных линий; явное название участка имеет приоритет. Исправлен критический дефект «Сохранить JSON»: сохраняется снимок canonical State.getDatabase(), а не реконструкция из плоского state; проверка целостности перед записью. На реальной приватной копии R6.1 локально проверены оба пути ручного сохранения, повторное открытие, 1188 позиций, 19 участков, 501 точка, 517 мероприятий, 3 черновика, 36 допущенных (20/16), повтор 0 изменений. Реальный DOM мастера в Chromium проверен в изолированном HTML с рабочими модулями на копии; навигация file:// и localhost ограничена средой. Синтетический полный браузерный тест расширен фактическим вводом/выгрузкой JSON и одинаковыми названиями на двух линиях. Не выгружать заводские данные/скриншоты в GitHub. Main не меняется; производственная приёмка Edge остаётся.

### Чек-лист Windows Edge (только копия JSON)

| Проверка | Критерий | Результат |
|---|---|---|
| Открытие действительной базы | В мастере имя загруженной базы, не демобаза | Не проверено в текущем сеансе |
| Выбор всех линий и одной линии | Только фактические участки, одноимённые различаются по линии, корректный areaId | Не проверено в текущем сеансе |
| Обычный мастер | Предпросмотр без записи; только участок + обслуживание + периодичность; готовые задачи согласно QA, без выдуманных сроков | Не проверено в текущем сеансе |
| Сохранение и повтор | Черновики/допустимые изменения сохраняются только после подтверждения; повтор без изменений; прежние ручные маршруты и история сохранены | Не проверено в текущем сеансе |
| Сохранение JSON и reload | Сохранить в отдельный новый файл, снова открыть, сверить состав участков, точек, задач, маршрутов и историю | Не проверено в текущем сеансе |
| Расширенный режим | При наличии фактических оснований проверить сроки, смены, ППР линий, прогноз, план/факт, печать и CSV на тестовой копии | Не проверено в текущем сеансе |
