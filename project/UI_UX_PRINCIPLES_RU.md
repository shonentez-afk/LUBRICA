# LUBRICA — постоянные UI/UX принципы

## 1. Не делать полный редизайн без необходимости

Сохранять привычную архитектуру приложения:
- меню;
- карту;
- дерево;
- карточки;
- общую визуальную модель.

Изменения должны улучшать рабочий сценарий, а не заново переучивать пользователя.

## 2. Роли вкладок карточки

- **Точка** — идентификация и место.
- **Мероприятие** — фактическое действие.
- **Анализ** — выбор материала и связанный анализ.
- **Расчёт** — итог, параметры и «Подробнее».

Не смешивать эти роли обратно в одну перегруженную форму.

## 3. Simple / Expert

Это системный принцип всего приложения.

### Simple
Показывает:
- что делать;
- сколько;
- когда;
- какой материал;
- основные предупреждения.

Скрывает лишние raw designations, fallback-детали и коэффициенты.

### Expert
Добавляет:
- OEM/source details;
- исходные параметры;
- формулы/коэффициенты;
- fallback;
- provenance;
- техническое обоснование.

## 4. Единый lifecycle действий

- изменил данные точки → сохранил точку;
- выполнил расчёт → применил результат;
- утвердил мероприятие → оно участвует в плане.

Не смешивать «рассчитать», «сохранить» и «утвердить» в одну неявную операцию.

## 5. Источники и обоснование

Должно быть единое понятное место, где пользователь может увидеть:
```text
объект → расчёт → результат → источник → почему принято именно это
```

## 6. Полная замена

Если full renewal не применяется, блок должен быть компактным и не перегружать пользователя.

## 7. UI не должен менять доменную модель

Нельзя ради красивого интерфейса:
- сливать несколько мероприятий в одну запись;
- создавать виртуальные узлы;
- терять taskId;
- скрывать unresolved state;
- менять физическую структуру машины.

## 8. Мобильное направление

Мобильный интерфейс требует отдельной mobile-first разработки. Нельзя просто сжимать desktop UI и считать это готовым мобильным приложением.
