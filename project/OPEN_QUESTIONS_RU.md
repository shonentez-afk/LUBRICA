# LUBRICA — открытые вопросы и незакрытые пункты

Этот файл содержит только актуальные или явно не закрытые вопросы. Старые дефекты не считаются открытыми, если они уже закрыты релизом и не воспроизведены снова.

## A. PP-53736 — подтверждённые открытые вопросы

### 1. R77, Линия 1, позиции №5–№8 — Issue #1
В persisted базе сохранено M1, а сборочный чертёж 53736 даёт machine-OEM hint M3 для второй группы из четырёх R77.

Статус:
- конфликт обнаружен;
- программа не перезаписывает положение автоматически;
- четыре точки помечены для инженерной проверки.

Для закрытия:
- подтвердить фактическое монтажное положение на установленном оборудовании/шильдике;
- после подтверждения применить корректный OEM-объём;
- сохранить provenance;
- добавить/обновить acceptance.

### 2. Запись `5000/500 h` — Issue #2
Значение 500 не имеет доказанной трактовки.

Статус:
- raw запись сохраняется;
- рабочий интервал замены масла = 5000 ч;
- автоматическое событие «первая замена 500 ч» не создаётся.

Для закрытия:
- найти первичный источник, однозначно объясняющий 500;
- до этого не делать предположений.

### 3. Фактические M1–M6 для отдельных SEW — Issue #3
Для K37, KF37R17 и S37 окончательный объём масла зависит от фактического установленного положения/исполнения.

Для закрытия:
- подтвердить положение по реальному узлу/шильдику/уровню;
- применить соответствующую OEM-строку.

## B. Документация

### 4. Актуальность встроенного руководства и скриншотов — Issue #4
В архивной карте встречается указание на скриншоты старой версии интерфейса. После серии 1.0.27–1.0.33 интерфейс и расчётная логика заметно развивались.

Статус: требуется отдельный аудит документации перед следующим крупным production-baseline.

Это не означает, что руководство сейчас неработоспособно; требуется именно сверка его актуальности с текущей версией.

## C. Правило списка

Новые незакрытые инженерные вопросы, подтверждённые дефекты и блокеры должны добавляться сюда или в GitHub Issues.

После закрытия пункт:
- переносится в release note/chronicle;
- удаляется из активного списка;
- не должен оставаться вечным TODO.
