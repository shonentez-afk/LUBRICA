# LUBRICA — индекс инженерных источников

## Назначение

Этот файл не заменяет Source Registry приложения. Он нужен как проектная карта: какие классы внешних источников лежат в основе инженерной логики и где искать локальные доказательства.

## Приоритет

1. Документ конкретной машины.
2. Документ производителя установленного компонента.
3. Локальная проверенная OEM-таблица.
4. Явно помеченный инженерный fallback.

## Основные группы источников

### Izoteh PP-53736
Локальные документы и листы чертежей хранятся в:
`assets/oem/izoteh/`

Используются для:
- физической топологии машины;
- состава приводов;
- интервалов обслуживания;
- machine-OEM hints;
- проверки фактической структуры двух линий.

### Подшипники и корпуса
Источники распределены по:
- `bearings/SOURCES_*.txt`;
- `calculations/`;
- специализированным OEM datasets в `components/`.

Ключевые OEM направления: SKF, NSK, FAG/Schaeffler, NTN-SNR, Timken.

### Вентиляторные узлы
Зафиксированные контексты включают Ferrari, Ventapp, Tröster, SNR ZLG, SKF SNL.
Критическое правило: не переносить метод одного OEM на другой без доказательства.

### Редукторы
Используются OEM-таблицы и machine-specific данные для SEW, Tandler, Bonfiglioli, Rossi и других производителей, присутствующих в реальном парке.

Критические параметры:
- точная модель;
- монтажное положение;
- объём масла;
- число независимых полостей;
- класс/тип масла;
- интервал;
- источник и ревизия dataset.

## Что нужно хранить рядом с новой логикой

Для каждого нового OEM/машины по возможности сохранять:
- исходный PDF/таблицу/чертёж;
- краткое описание, какой параметр из него взят;
- номер страницы/таблицы;
- локальный dataset;
- targeted test;
- release note/acceptance, где впервые принято решение.

## Нельзя

Не использовать внешнюю ссылку как единственное доказательство критического runtime-значения, если документ можно легально сохранить локально.
