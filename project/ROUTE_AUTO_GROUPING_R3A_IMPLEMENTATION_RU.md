# LUBRICA — R3A: автоматическое формирование по участкам, виду обслуживания и периодичности

**Согласовано 25.11.2026.** Ветка `feature/route-safety-ux-20261119`, [Draft PR #23](https://github.com/shonentez-afk/LUBRICA/pull/23) поверх Stage 5D PR #22. Main и production JSON не изменять.

## Принятое пользователем правило
Единственная группировка автоматических маршрутов: **участок + вид обслуживания + периодичность**. Идентификатор линии служит для однозначной принадлежности участка. Семейство машины (конвейер, пила, вентилятор, двигатель и т. п.) **не входит в ключ**. Тип оборудования показывается только как реквизит физической точки внутри маршрутного листа.
- Вид обслуживания = категория подтверждённой физической точки + канонический тип операции. Например bearing/regrease, bearing/grease_full_replacement, gearbox_oil/oil_level_check, gearbox_oil/oil_change, chain/lubricant_apply.
- Операции разных видов, даже на одной точке, не смешивать. Разные машины и материалы внутри совместимого вида/интервала не требуют отдельных групп; подготовка материалов остаётся раздельной.
- Группировать только существующие taskId, без создания новых точек и мероприятий.
- Интервалы нормализуются по размерности и величине: 1 неделя = 7 дней; 1 год = 12 месяцев; 500 ч = 500 часов; 1 месяц != 30 дней; моточасы != календарные дни. Не распознавать неоднозначную запись 5000/500 ч по первому числу. «По состоянию» и событийные работы не являются периодическими маршрутами. При несовпадении структурированных полей и текста — уточнение, не автоподстановка.
- Данные проходят существующий семишаговый QA и проверку привязки физической точки/узла к оборудованию и участку; необслуживаемые, отключённые, obsolete и неизвестные категории не включать.

## Реализация
- `routes/route-auto-grouping.js`: классификация, строгая нормализация интервала, ключ [lineId, areaId, serviceKey, scheduleKey], read-only preview. Модель группировки `area_service_interval_v1`.
- `routes/route-engine.js`: `previewAutoGrouping` и `applyAutoGrouping`. Подтверждённая транзакция по копии БД; сверка токена актуальности, единственная запись после проверок. Только новые или свободные существующие черновики. Идентификатор, имя, код, метаданные группы и ревизии сохраняются. Ручной порядок обхода не меняется; новые задания добавляются по исходному детерминированному порядку оборудования/точек, не выдавать за оптимизированный маршрут.
- `routes/routes-ui.js`: кнопки автоматического формирования и обновления открывают **один мастер** с фильтром линии и участка, количеством изменений и расшифровкой исключений. Без выбора дополнительных принципов группировки.
- Не мигрировать старые ручные/автоматические маршруты без отдельной ручной сверки. Занятые в текущих маршрутах taskId и ручные исключения не дублируются. Архив/снимки/план не меняются. Активные маршруты и черновики с незавершённым планом не дополняются автоматически. Если состав перестал соответствовать ключу, вывести конфликт, ничего не переносить незаметно. Повтор без изменений не записывает базу.
- `syncRoutes` при подключённом новом модуле требует явного подтверждения; не выполнять скрытую старую синхронизацию. Ручной конструктор маршрутов сохранён для осознанного выбора.
- Отдельная граница R3A: **новые типизированные автомаршруты только черновики**. Активация, планирование и старт не разрешаются, пока не принят R3B (индивидуальные даты/наработка и состав планового задания). Старые маршруты не переводятся в этот режим. Не путать равенство интервала с равенством текущего срока. R3B реализован следующим пакетом; см. [ROUTE_TASK_DUE_R3B_IMPLEMENTATION_RU.md](ROUTE_TASK_DUE_R3B_IMPLEMENTATION_RU.md). Прежняя блокировка активации заменена проверкой индивидуальных оснований и точного планового задания.

## Приёмка
- `test/test_route_auto_grouping_r3a.js`: 9 групп на синтетической базе; конвейер/вентилятор в одном маршруте, разные участок, вид и интервал — разные маршруты; календарные/часовые размерности, QA, дубли, неизменный архив, транзакция, устаревший preview, сохранение порядка, блокировка активации.
- `test/test_route_auto_grouping_r3a_browser.py`: реальные JS-модули и синтетическая БД, Chromium 1440/768; мастер, фильтры, preview без записи, явное создание черновиков и повтор без дублей.
- `test/run_all.sh` и GitHub Actions R1+R2+R3A: полная регрессия; отдельный ZIP для Edge `file://` только с программой. Не использовать производственную базу, пока не закрыты К3/М1 и ручная приёмка.

## Продолжение R3B (реализовано в следующем пакете)
Разделить постоянный маршрут и плановое задание по индивидуальным срокам taskId; хранить надёжное основание первого срока/последнего факта/моточасов, проверять пропуски и прогнозы. Не вычислять моточасы из календаря без явной маркировки прогноза. Не активировать типизированные маршруты автоматически до приёмки R3B.
