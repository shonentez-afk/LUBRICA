# LUBRICA — политика технических источников и инженерных доказательств

## 1. Общий принцип

Программа не должна выдавать техническое значение только потому, что «похожее число есть в справочнике». Для значимых расчётных данных должна быть понятна цепочка происхождения.

## 2. Приоритет источников

Рабочий порядок:

1. паспорт, руководство, чертёж или подтверждённый источник конкретной машины;
2. OEM-документация установленного компонента;
3. локальная проверенная OEM-таблица LUBRICA;
4. инженерный fallback — только когда более сильного источника нет и с явной маркировкой.

Machine-specific source имеет право уточнить общую component-level логику.

## 3. Нельзя

- подменять одного OEM другим без доказанной эквивалентности;
- переносить данные между похожими обозначениями только по сходству строки;
- трактовать моторные обозначения как параметры редуктора;
- скрывать конфликт двух источников;
- превращать неопределённую запись в точный интервал без доказательства;
- автоматически утверждать результат после изменения OEM dataset;
- суммировать независимые масляные полости так, будто это одна полость.

## 4. Что сохранять вместе с результатом

По возможности:
- производитель;
- модель/семейство;
- источник;
- номер/страница/раздел или идентификатор таблицы;
- raw исходная запись;
- выбранные исходные параметры;
- версия локального dataset;
- признак user_confirmed / machine_oem / component_oem / fallback;
- предупреждения и конфликты.

## 5. Фактическая установка имеет приоритет

Монтажное положение, фактический шильдик, уровень масла, исполнение корпуса и установленная конструкция имеют приоритет над предположением из общего обозначения.

Если программа имеет только подсказку из чертежа, она должна маркировать её как hint/review, а не молча перезаписывать пользовательское подтверждение.

## 6. Неопределённость — допустимый результат

Если источник не позволяет однозначно понять значение, LUBRICA должна хранить raw запись и статус unresolved.

Пример: запись `5000/500 h` без подтверждённого контекста должна оставаться unresolved. **Для конкретной PP-53736 этот вопрос уже закрыт в принятом machine-service workflow:** 5000 ч — рабочий интервал замены масла, 500 ч — first service. Это заключение относится к подтверждённому кейсу PP-53736 и не распространяется автоматически на другие редукторы или OEM.

## 7. Локальные копии источников

Критически важные OEM-источники, на которых основана runtime-логика, желательно хранить в репозитории или как release/source assets, чтобы расчёт оставался воспроизводимым даже при исчезновении внешней ссылки.
