# LUBRICA — Stage R5: автоматизация формирования маршрутов и рабочих заданий

**25.11.2026.** Единый крупный пакет поверх принятого автоматическими тестами R4.1, Draft PR #23. Main и заводской JSON не изменяются.

## Согласованный принцип
Постоянный маршрут = участок + вид обслуживания (категория реальной точки и операция) + точная периодичность. Семейство оборудования, смена, доступность и трудоёмкость не входят в ключ. Недельные эквиваленты точны; месяц не равен 4 неделям, моточасы не равны календарному интервалу. ППР каждой линии — отдельная фаза 14 дней.

## Реализация
- В действующих кнопках автоматического формирования/обновления открывается **единый мастер** R5; прежнее быстрое создание черновиков оставлено доступным. Шесть разделов, единый предварительный результат, явное подтверждение. Изменения рассчитываются на копии, сверяется полный токен состояния, единственная запись при подтверждении. Не меняются физические точки, утверждённые смазочные нормы, интервалы, факты.
- Сверка свободных typed auto routes: новые задания, изменившаяся группа, утратившие готовность точки, порядок и сигнатура норм/материалов/труда. Перенос между группами только в одной согласованной транзакции; защитить ручные/копии, исключения, дубли и незавершённые задания. Если целевой маршрут защищён, исходный не отсоединяется. Пустые группы архивируются с прежним составом и историей. Изменения активного состава с отсутствующими сроками переводят маршрут в явно показанный черновик; активация только при полной готовности.
- Исходный срок: восстановление только из завершённого мероприятия с точной сигнатурой (физическая точка, операция, интервал) и выполненным результатом. Для отсутствующих календарных оснований — явно указанная следующая или последняя фактическая дата, массово в выбранном охвате/виде. Для моточасов — явное подтверждение общего счётчика конкретного оборудования, последнее обслуживание, чтение, дата и необязательный прогноз. Настроенные сроки, открытые задания, ручные маршруты не перезаписывать.
- Общий порядок обхода участка хранится в routeAutomation.walkOrder. Новые группы наследуют его; существующий ручной порядок меняется только при отдельной отметке и отсутствии открытых заданий. Новое оборудование добавляется по коду.
- task.routePolicy: явное условие «только ППР», индивидуальная трудоёмкость и разрешённое досрочное окно с инженерным основанием. Ранее заданный доступ ППР сохраняется консервативно при изменении интервала. При изменении ключа раннее окно недействительно. Досрочность по моточасам не разрешается. Календарное окно меньше интервала (для месяцев консервативная граница 28*n-1), до 90 дней. Не менять исходный срок; факт досрочного выполнения фиксируется только из подтверждённого рабочего назначения. Следующий срок по реальному выполнению.
- План: отдельные задания по условиям доступа, при включённой опции — разделение больших новых заданий по целым физическим точкам с учётом чистого времени одного смазчика, времени перехода и подготовки. Не дробить мероприятие. Не переписывать уже зафиксированный план. При подготовке суммируются материалы точного состава; ошибки подготовки блокируют транзакцию с планом. При отсутствии нормы времени сохраняется прежняя норма маршрута. Порядок внутри класса сохраняется.
- Рабочий календарь: прежние до 3 смен, численность и индивидуальная ёмкость, ППР каждой линии. Использовать разрешённое окно и доступность, не назначать до него. При явной настройке балансировать по неделям/сменам; при отсутствии места позднее исходной даты только с разрешением и причиной, ближайший допустимый день предпочтителен. Уже назначенные работы не двигаются автоматически. Существующий движок выполняет только одно задание одного маршрута одновременно: суммарная длительность его отдельных заданий в смене ограничена ресурсом одного человека; другие маршруты могут занимать другие ресурсы.
- Прогноз 4/12/26/52 недели: техническая потребность с гипотетическими будущими повторениями, календарный и обозначенный часовой прогноз, сравнение с недельной ёмкостью, конфликты ППР, отсутствующие основания. Только чтение, не создавать будущих фактов или обязательных заданий. Это эвристика, не оптимизационный решатель и не точный производственный календарь.
- Сохранены локальная работа Edge file://, существующие UI, быстрый мастер, QA, архив, ревизии, план/факт, печать. Внешние JS/WASM решатели не подключены: используется локальная детерминированная эвристика без зависимостей.

## Не заявлять производственную готовность без проверки
Пока нет именного графика сотрудников, индивидуальных ротаций/исключений ППР, загрузки с АСУ ТП, полноценной параллельной обработки нескольких заданий одного постоянного маршрута и точного геометрического маршрута. Алгоритм балансировки консервативный; сравнение внешних оптимизаторов не проведено. Импорт произвольного внешнего журнала факта не реализован: использован проверяемый внутренний факт и явно введённые основания. ФРВ не превращает наблюдение автоматически в норматив — норматив задаётся и подтверждается вручную. Даты/ресурсы/нормативы предприятия необходимо настроить по фактическим данным. Требуется ручной Edge file:// тест на резервной копии и приёмка K3/M1 до эксплуатации. PR остаётся Draft; не объединять main без приёмки.
