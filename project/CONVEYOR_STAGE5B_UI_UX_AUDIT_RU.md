Проверены работа кнопок/чекбоксов, значение и порядок полей, сохранённое реальное имя точки, запрет без источника, предупреждение при смене типа, выгрузка CSV конкретной машины и отсутствие лишней горизонтальной прокрутки **в изолированном тестовом контуре форм**. ## 4. Оставшиеся реальные ограничения — не скрывать

1. **Мобильная оболочка всей LUBRICA не принята.** Существующая десктопная сетка задаёт `body{min-width:760px}` при узком экране; браузерный тест **изолирует конвейерные формы от оболочки**, задавая min-width:0 только в тестовом fixture. PASS на 390 px подтверждает **формы и раздел Контроль**, а не полноценное удобство всех вкладок с телефона. Не перепроектировать всю десктопную систему внутри конвейерного PR без отдельного проекта мобильного UX.
2. **Невозможно подтвердить все физические опоры по имени ТМЦ.** Сведения в реестре — только инженерная очередь. По исходной базе до 226 записей, похожих на отдельные конвейеры, требуют доказательства реально обслуживаемых мест; группа/родитель/подсистема не становятся самостоятельными точками.
3. Тестовая `Plant Point` QA в браузерной синтетической базе показывает `0%`, потому что используется заглушка аудита **только для теста интерфейса**. Это не показатель реальной готовности завода.
4. Реальные права доступа, стабильность `file://`, DPI/масштабирование Windows, печать/экспорт с пользовательскими параметрами, физическая точность всех source bindings проверяются **отдельно на резервной копии** базы пользователя. Нельзя выдавать Chromium fixture за производственную приемку.
5. OEM-пробелы, реальные интервалы и дозы, подбор материалов, недостающие физические точки остаются `REVIEW/SOURCE_REQUIRED`. Никаких автоматических `approved`, no virtual supports, не создавать production routes.
6. Центрифуги со всеми дочерними подсистемами (включая шпиндельный масляный туман) и охлаждение — `OUT_OF_SCOPE`, не менять их записи.
