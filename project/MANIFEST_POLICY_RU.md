# LUBRICA — контроль полноты GitHub

В проекте используются два разных контрольных манифеста.

## 1. Эталон исходного baseline 1.0.33.67

`project/baselines/FILE_MANIFEST_SHA256_v1.0.33.67.txt`

Это неизменяемый SHA-256 снимок файлов, которые были перенесены из полного baseline LUBRICA 1.0.33.67.

Он нужен для ответа на вопрос:

> «Совпадает ли GitHub-копия исходной поставки 1.0.33.67 с тем архивом, из которого выполнялась миграция?»

Этот файл **не должен автоматически обновляться** после изменений проекта.

## 2. Текущий манифест состояния main

`project/CURRENT_FILE_MANIFEST_SHA256.txt`

Он генерируется GitHub Actions после изменений в `main` и отражает текущее фактическое состояние репозитория, включая:
- код;
- тесты;
- README;
- project memory;
- workflow;
- документацию;
- OEM/source материалы;
- все новые файлы, появившиеся после миграции.

Сам `CURRENT_FILE_MANIFEST_SHA256.txt` исключается из собственного списка, чтобы не создавать рекурсивное изменение хеша.

## 3. Контрольное правило

При проверке полноты проекта:
- baseline 1.0.33.67 сверять с immutable baseline manifest;
- текущее состояние GitHub сверять с CURRENT manifest;
- если добавлен новый проектный файл, он обязан автоматически появиться в CURRENT manifest;
- если изменился файл, его SHA-256 в CURRENT manifest обязан измениться.

## 4. Исторический путь

`project/FILE_MANIFEST_SHA256.txt` сохраняется для обратной совместимости и соответствует исходному baseline 1.0.33.67. Для новых проверок использовать явные пути выше.
