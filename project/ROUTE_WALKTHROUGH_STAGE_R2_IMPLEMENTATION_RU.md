# LUBRICA — Stage R2: экран обхода физических точек

**Дата:** 19.11.2026. **Ветка:** `feature/route-safety-ux-20261119`. **Draft PR:** [#23](https://github.com/shonentez-afk/LUBRICA/pull/23), основан на Stage 5D PR #22. **Пользовательская база и `main` не изменялись.**

## Цель
Рабочий маршрутный лист был подробной таблицей с десятью колонками. Для ежедневного обхода это создаёт лишнюю горизонтальную прокрутку и повторные записи на несколько операций одного физического места. В Stage R2 добавлен **переключаемый компактный режим обхода** без изменения существующего движка, данных и печатного маршрутного листа.

## Исполнение
- `routes/route-compact-ui.js` — новый самостоятельный read-only presenter. Использует штатные `modelForRun` и `model.groups`, группирует подряд идущие операции одной **физической** точки по `pointKey` и `routeStep`, не создаёт новые места, задачи или виртуальные опоры.
- На карточке: шаг, оборудование/код, узел, физический ID точки, назначенные операции, наименование и код материала/инструмента, исходная плановая норма, OEM/технологические шаги, результат, факт, причина отклонения.
- Фильтр по всем/необработанным/с отклонениями/обработанным точкам и быстрый переход к необработанной.
- `routes/routes-ui.js`: переключение «Обход по точкам» ↔ «Подробная таблица». Одновременно в DOM присутствует **только одно** представление редактируемых полей; это исключает столкновение данных при сохранении. Переключение только UI, без записи в БД.
- Смена статуса в компактном режиме сохраняется через `LubricaChecklistEngine.updateTask`, после чего обновляются прогресс и карточки. Для пропусков/«не требуется» причина сохраняется при вводе в `deviationReason`, завершение маршрута по-прежнему требует заполненной причины.
- Экран автоматически использует компактный режим при открытии; подробная таблица доступна по переключателю. Кнопка печати временно показывает штатную таблицу и возвращает пользовательский режим после `afterprint`.
- Новый `assets/route-compact.css`: оформление согласовано с существующей палитрой приложения, ширина адаптируется, ниже 900px список маршрутов и рабочий лист расположены вертикально. Не означает полной сертификации мобильной версии.
- `index.html` загружает модуль и CSS локально, Edge `file://` не требует интернета.

## Инварианты
- Не изменять `routeTaskIds`, `routeSnapshot`, историю, ревизии, план/факт, ФРВ, оригинальный JSON, расчётное ядро, OEM-источники и формат CSV/Excel/PDF.
- Все виды используют **одни и те же taskId**. Одна точка может иметь несколько действий; все операции независимы для статуса и факта.
- `completed`, `skipped`, `not_applicable` не объединять в один «выполнено». `resolvedPercent` отражает обработку, `percent` — фактически выполненные мероприятия.
- Старые выполненные маршруты показывать read-only по снимку факта, даже если карта и актуальный маршрут изменились.
- Временная редакция поля — только у активного выполнения; черновик маршрута нельзя запускать.
- Чек-лист, материалы и доступ остаются основаны на утверждённых мероприятиях; неполные/неподтверждённые данные не маскировать.

## Автоматическая приёмка
- `node test/test_route_execution_compact_r2.js`: 2 физические точки / 3 мероприятия, порядок, статусы, пропуски, фильтры, escaped HTML, read-only и неизменность снимка.
- `python3 test/test_route_execution_compact_r2_ui.py`: подключение модулей, переключение, печать и ввод фактических результатов.
- `python3 test/test_route_execution_compact_r2_browser.py`: настоящий `routes-ui.js` + `checklist-engine.js` в Chromium с синтетической машиной, три viewport (1440/768/390), запись причины пропуска, восстановление после печати, responsive screenshots; нет реальных данных завода.
- Оба Node/Python теста включены в `bash test/run_all.sh`, запускается GitHub Actions `route-safety-r1.yml`.
- Отдельный workflow `route-walkthrough-r2-browser.yml` загружает скриншоты и проверяет UI в Chromium.

## Граница приёмки
Автоматические проверки не заменяют Edge `file://` на **копии** заводской базы. Реальные производственные маршруты не формировать до принятия конструкторов и полной физической карты. Не объединять Draft PR с `main` до согласования и ручной проверки. Продолжение работы над другими семействами оборудования вне Stage R2.
