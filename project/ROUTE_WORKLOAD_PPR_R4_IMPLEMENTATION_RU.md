# LUBRICA — R4: нагрузка, смены и ППР линий

**25.11.2026.** Продолжение R1–R3B в Draft PR #23 поверх Stage 5D PR #22. Main и производственная база не изменяются.

## Согласованные требования
- Автомаршруты по-прежнему: участок + вид обслуживания + периодичность. Семейство машины не учитывается.
- ППР на каждой линии раз в **14 календарных дней**, с индивидуальной датой отсчёта для линии. Пользователь явно вводит известную дату ППР; система вычисляет фазу графика, не выдавая её за факт остановки.
- Технический срок мероприятия, накопительный порог моточасов, нормы, состав задания и ревизия не изменяются при административном распределении работ.
- Нельзя автоматически считать всю смазку работами ППР. Для маршрутов, все задания которых требуют ППР, оператор явно ставит ограничение «только ППР». Это параметр назначения, не ключ формирования маршрута.
- При отсутствии свободной смены либо если ближайший ППР позже исходной даты, показать конфликт. Не переносить задание без явного разрешения и причины; не назначать до исходного планового дня (раннее обслуживание не согласовано в R3B).

## Реализация
- `routes/route-workload.js`: root-настройка `routeWorkload` (рабочие дни, доступные минуты каждой смены, ppr anchors по lineId, pprRouteIds). Нагрузка учитывает назначения, незавершённые/завершённые работы и их плановые минуты; неизвестная смена или длительность блокирует автоматическое назначение на день. Планировщик распределяет только незапущенные работы без назначения в порядке ранних сроков. Задания длиннее смены не дробятся автоматически.
- `workAssignment` содержит рабочую дату, смену, причину и время назначения; `workAssignmentHistory` сохраняет переносы/снятия. Не переписываются `plannedDate`, `dueEntries`, `taskIds`, `checklistSnapshot`, нормы, ревизии. Токен предварительного просмотра защищает от устаревшего подтверждения.
- `routes/route-workload-ui.js` и `assets/route-workload.css`: кнопка «Нагрузка, смены и ППР» внутри действующего окна плана; недельный/месячный и произвольный период; настройки, явный preview/apply, ручное назначение/перенос, индикаторы загрузки и отдельные маркеры ППР каждой линии.
- `routes/route-planning.js`: исходный плановый день и рабочая дата разделены; календарь отображает назначенную дату, технический срок сохраняется для контроля просрочки.
- `checklist/checklist-engine.js` / `routes/routes-ui.js`: назначенные работы запускаются в указанную дату/смену, PPR-only требуют задания на ППР своей линии; проверка также в engine. При запуске рабочее назначение фиксируется в снимке, дата/смена защищены от последующего произвольного редактирования. Старые неназначенные обычные маршруты сохраняют прежний порядок работы.

## Ограничения
График ППР представляет одну фазу 14 дней для каждой линии; перенос конкретного ППР/отмену в производстве пока необходимо согласовать вручную (не подтверждать несоответствующее задание). Доступные минуты — суммарный ресурс смазочных работ смены, не персональный табель или календарь отпусков; рабочие дни и ёмкость должны быть явно настроены. Для маршрутов со смешанными требованиями доступности не предполагается автоматическая классификация остановки; требуется уточнить состав и условия. Ручная Edge file:// проверка на резервной копии базы и K3/M1 обязательны до производственного использования; PR остаётся Draft.
