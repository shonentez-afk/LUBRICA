# LUBRICA Stage 5B — конструкторы реальных конвейеров

**Ветка:** `feature/stage5b-conveyor-families-20261105` · **PR #22** · дата 2026-11-05.
**Статус:** тестовая реализация для кодовой приёмки. Не является принятым релизом и не содержит production JSON.

## Цель

Предметно расширить единый `Conveyor Arrangement` под фактический парк, не заводя параллельные калькуляторы и не выдавая виртуальные опоры за реальные.

Источник аудита: `Филиал_завода__Техно__г._Юрга(20261105-040121).json`, 293 записи equipmentType conveyor, 226 похожих на отдельные машины, 35 групп, 32 связанные системы. Количества являются *классификацией по названиям*; физические места смазки и OEM-конструкции требуют отдельной сверки.

## Реализация и ограничения

| Конструкция | Поведение в Stage 5B |
|---|---|
| Ленточный / ременный | `belt`: сохранён существующий мастер с двумя подтверждёнными валами; при отсутствии валов не строить по умолчанию 4 опоры |
| Скребковый / отходов | `chain_scraper`: сохранена совместимость с существующей схемой, подтверждаются физические валы, реальные подшипники и цепи |
| Цепной / KTR | `chain`: собственный подтип и блоки фактических цепных контуров, валов, привода, опор; не наследовать 4 опоры |
| Роликовый | `roller`: блоки секций/роликов, фактических обслуживаемых опор, приводов; нет досмазывания герметичных роликов по названию |
| Ламельный | `lamella`: цепи, опоры, привод, система подачи смазки/охлаждения как дочерняя подсистема |
| Шнековый | `screw`: шнек/вал, реальные опоры, привод; без фиктивных валов/подшипников |
| Угловой / поворотный | `turning`: подтверждаемые механизмы поворота, реальный привод, цепи/опоры |
| Комбинированный | `hybrid`: ленточная и роликовая части раздельно, не трактовать автоматически как `belt` |
| Весовой / сглаживающий | `weighing`: весовая часть — контекст; обслуживание только по физическим узлам |
| Не определён | `unknown`: статус требует уточнения, тип можно сохранить **без** новых смазочных точек |

Все конструкторы используют существующие `LubricaClassifier`, `LubricaConveyorArrangement`, `LubricaCandidateFinalizer`, `LubricaRotatingArrangement`, справочники и путь физическая точка → мероприятие. Stage 5B добавляет *профили сборки и реальные блоки ТМЦ*, **но не** включает доказанную индивидуальную геометрию 226 конвейеров: она требует паспорта/OEM и инженерного подтверждения в каждом агрегате.

### Защиты

- Импортированные **группы** не становятся конвейерами с точками.
- Фильтрация/смазка/охлаждение внутри конвейера сохраняются в его составе; соседние независимые конвейеры не поглощаются.
- `supportLayout=4` допустим только для belt/chain_scraper при двух найденных физических валовых ТМЦ; **две bearing-строки не доказывают два вала**.
- Для составных машин реальные найденные подшипники/цепи показываются как **неотмеченные** предложения; отмечается только подтверждённый физический объект с местом обслуживания, видом операции и выбранным ТМЦ.
- Смена вида ручного агрегата защищена при ранее введённых опорах или физических точках.
- Сохранение выполняется на клоне базы; при повторном применении guard защищает утверждённые tasks, routePlanItems, маршруты и факты.
- Можно сохранять тип конвейера с `review` и `createdPointIds=[]`, не добавляя выдуманные точки.
- `approvalStatus`, количественные нормы, интервалы, факты и маршруты не утверждаются и не пересчитываются автоматически.

### Подтверждение производственного обслуживания — 10108574

5 ноября 2026 года пользователь проверил в Edge тестовый конструктор оборудования **10108574 — «Конвейер роликовый охлаждающий»** и подтвердил, что **оба обнаруженных типа подшипниковых узлов UKF 207 и UCPA 208 требуют периодического досмазывания**. Их следует считать реальными обслуживаемыми типами для этой машины; не исключать по предположению о герметичности.

**Границы подтверждения:** это свидетельство пользователя об обслуживаемости двух типов узлов на конкретном конвейере, а не документированное число физических мест установки. Количество точек, их физические положения, доступ к маслёнкам, материал, доза и интервал должны отдельно подтверждаться перед утверждением мероприятий. Не распространять автоматически на все роликовые конвейеры и другие исполнения этих корпусов.

В интерфейсе оба типа показываются как реальные ТМЦ и могут быть выбраны для создания физически определённых точек с индивидуальными операциями; в Stage 5B **не** включать автоматическое назначение периодичности или дозы.

### Ручная проверка — шнековый конвейер `10110511` и аналог `10210511`

Скриншот 05.11.2026 для **`10110511`**, Линия 1 → Распиловки → «Система удаления пыли» `10110501`, подтверждает правильный subtype `screw`, **2 приводных агрегата** (ABB мотор и Bonfiglioli редуктор), 0 предложенных bearing-point. ### Stage 5B.6 — контроль покрытия ВСЕГО парка конвейеров (реализован в коде, field acceptance ещё не пройден)

**Зачем:** прежде классификатор разбирал отдельный конвейер, но не было доказуемого пути проверить, что пройдены **все** конвейеры двух линий. Из-за этого успешные unit-тесты на 12 примерах нельзя было считать завершением 226 самостоятельных машин.

Добавлен модуль `conveyors/conveyor-coverage.js`, подключённый в `index.html` и существующую вкладку **«Контроль»** через `qa/qa-ui.js`. Модуль принимает текущую `database` и **только читает** структуру, актуальную классификацию подтипа, component evidence, реальные существующие точки и связанные мероприятия. В «Контроль» появляется разворачиваемый блок «Покрытие конструкторов конвейеров», 12 машин на страницу, фильтры по линии, неизвестному подтипу, отсутствующим ТМЦ, наличию ТМЦ без точек, существующим точкам и составным машинам. Для каждого агрегата — исходный код, подтип, участок, число фактических ТМЦ, валов/контекстов, приводов, точек, дочерних конвейеров, следующее инженерное действие; переход в существующую структуру. Полная машинная ведомость экспортируется в CSV с `equipmentId`.

**Преднамеренно нет статуса «100% готов»:** распознавание названия, подтверждение только типа или даже наличие одной точки **не** означает, что все фактические физические места найдены. Состояния `SUBTYPE_UNKNOWN / EVIDENCE_MISSING / COMPONENTS_REVIEW / POINTS_REVIEW / COMPOSITE_REVIEW` — рабочая очередь до очной/паспортной приёмки и утверждения фактической комплектности каждой машины. Компонент не равен точке. В составе родителя `10111293` две дочерние самостоятельные машины `10111294`, `10111321`; точки детей не дублируются у родителя. Точки на обслуживаемых вспомогательных системах учитываются в **связанной** области конвейера, но сохраняют собственный `equipmentId` как источник.

**Дополнительный пробел импорта:** если отдельная машина называется «Конвейер …», но `equipmentType=other`, она также входит в QA-ведомость с исходным типом. Запись «Мотор-редуктор конвейера» без `equipmentType=conveyor` не считается конвейером. Производственный исходный тип не меняется, флаг лишних машин — только информация для инженера. Различаем `totalConveyorRecords` и `extraNamedRecords`; исходные 293 записей `equipmentType=conveyor` остаются исторической точкой сравнения, но не искусственным потолком.

**Исключения по требованию пользователя:** центрифуги и *всё дочернее оборудование в их иерархии*, а также охлаждающие подсистемы, полностью пропускаются при предметном анализе; счётчик `excludedScope` лишь поясняет их отсутствие в очереди. **Не** ставить им автоматически `NO_LUBE` и не трогать исторические точки, задачи, факты, маршруты. Следующим производственным семейством после полной приёмки конвейеров становится **распиловка**, а не центрифуги.
