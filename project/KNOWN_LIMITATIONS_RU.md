# LUBRICA — известные ограничения текущей архитектуры

Это не список багов. Здесь фиксируются сознательные или текущие ограничения production baseline.

## 1. Desktop-first

Основная production-база — desktop через Microsoft Edge / `file://`.

Мобильный Android executor не является текущей основной веткой.

## 2. Не multi-user cloud

Текущий baseline не является полноценной серверной многопользовательской системой с централизованной БД, правами, API и синхронизацией пользователей.

## 3. OEM coverage не бесконечен

LUBRICA расширяема, но не содержит автоматически достоверные данные для любого производителя и любой модели.

Если exact OEM data нет:
- не придумывать;
- использовать маркированный fallback только где допустимо;
- сохранять unresolved/review state.

## 4. Machine constructors зависят от подтверждённой физической схемы

Конструктор не должен угадывать недостающие опоры, приводы или масляные полости.

## 5. Некоторые значения требуют field confirmation

Пример: mounting position редуктора может зависеть от фактической установки, а не только от обозначения.

## 6. Внешний источник может исчезнуть

Поэтому критические OEM-документы, на которых основана runtime-логика, следует по возможности хранить локально.

## 7. Документация интерфейса может отставать

После серии 1.0.27–1.0.33 необходимо периодически сверять встроенное руководство и скриншоты с текущим UI.

## 8. Source-dependent tests

Некоторые проверки XLSX могут SKIP, если исходный внешний файл отсутствует. Такой SKIP не равен product failure, если он ожидаемый и явно зафиксирован.
