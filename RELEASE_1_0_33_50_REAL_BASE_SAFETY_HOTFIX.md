# LUBRICA 1.0.33.50 — Real Base Safety Hotfix

База: `LUBRICA 1.0.33.49` + проверка на фактической рабочей JSON-базе предприятия от 2026-09-18.

## Исправлено по фактической базе

1. Монтажные закрепительные втулки H 3xx с `candidateState=excluded/rejected` больше не попадают в список обслуживаемых ТМЦ конструктора системы качания.
2. TOLLOK TLK 400 классифицируется как бесшпоночное зажимное/стяжное устройство вала, а не как самостоятельная втулочная точка смазки.
3. Закрытые подшипники `2RS/2RS1/2RSH/2Z/ZZ/DDU/VV` не создают автоматическое плановое досмазывание без отдельного OEM-подтверждения — правило действует и для выбранного ТМЦ, и для ручной маркировки.
4. Добавлен отдельный SKF SNH housing-context. Для `SNH 522 TC + 22222 EK` расчётным объектом остаётся внутренний подшипник, а корпус хранится отдельно и не маскируется под SNL.
5. Корпус SNL/SNH нельзя ошибочно подтвердить как обычный внутренний подшипник; мастер требует тип корпусной опоры и фактический подшипник.
6. Сохраняются исправления 1.0.33.49: scoped cleanup, сильная контекстная привязка, ручной SNL parity, раздельные `non_serviceable/no_connection`, удаление manual elements.

## Реальная база

На фактической базе обнаружены и проверены:
- Линия №1: `Система качания Линия №1`, 6 связанных элементов; `SNH 522 TC + 22222 EK`; закрытые `6316-2RS1`.
- Линия №2: `Система качания Линия №2`, 8 связанных элементов; `SNL 528 + 22228 CCK/W33`; TOLLOK TLK 400; H 3128.
- До применения конструктора у обеих систем нет generated Oscillating points/tasks, поэтому миграция начинается с чистого состояния.

## Совместимость

Рабочая JSON-база не изменяется при аудите. Схема остаётся `2.0`; normalizer сохраняет обратную совместимость с базами, у которых `appVersion` в файле старше текущего приложения.
